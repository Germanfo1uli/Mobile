# ALTHUNT — лабораторные работы по ПМУ

Android-приложение на Kotlin и Jetpack Compose, которое развивается по этапам практических работ: от первого экрана и регистрации игрока до вкладок, игрового процесса, базы результатов и сетевых данных.

## Что реализовано

- стартовые экраны приложения;
- регистрационная форма игрока: ФИО, пол, курс, сложность и дата рождения;
- вычисление и отображение знака зодиака;
- вкладки «Досье», «Правила», «Авторы» и «Настройки»;
- правила игры из HTML-ресурса;
- настройки сложности, скорости, количества альтушек, интервала бонусов и длительности раунда;
- карта с первой доступной вылазкой и двумя закрытыми уровнями;
- движущиеся цели, попадания, штрафы, таймер и экран итогов;
- выбор зарегистрированного игрока из PostgreSQL и вкладка рекордов;
- REST API для регистрации игроков, хранения настроек и результатов;
- PostgreSQL с автоматическими миграциями и таблицей рекордов;
- серверная логика раундов, попаданий, штрафов и проверенного сохранения результатов;
- синхронизация анкеты и настроек Android-приложения с сервером;
- модульный тест расчёта знака зодиака и интерфейсные тесты Compose.

## Бэкенд и PostgreSQL

### Облачный деплой

В корне находится `render.yaml`: он создаёт бесплатный Render Web Service из Dockerfile
бэкенда, проверяет `/api/health` и автоматически выкатывает каждый push в ветку `lab5`.
Секрет `DATABASE_URL` при первом создании Blueprint берётся из Neon PostgreSQL и никогда
не сохраняется в Git. Для облака включён TLS к базе, а фоновая проверка завершённых раундов
выполняется раз в 30 секунд, чтобы не расходовать бесплатный лимит Neon лишними запросами.

GitHub Pages для API не подходит: он публикует только статические файлы и не запускает
Node.js/PostgreSQL. GitHub в этой схеме хранит код и запускает автоматический деплой Render.

### Автоматический запуск на другом Windows-компьютере

Склонируйте репозиторий, переключитесь на ветку `lab5` и дважды щёлкните
`scripts/start-local-lab5.cmd`. Скрипт не требует Docker:

- найдёт установленный PostgreSQL и использует его программы, не меняя существующие базы;
- если PostgreSQL не установлен, скачает официальную переносимую версию 17.11;
- скачает официальный переносимый Node.js 24.21.0;
- проверит контрольные суммы архивов;
- создаст постоянную локальную базу `bugs` в `%LOCALAPPDATA%\AltHuntLocal`;
- установит зависимости, запустит API и применит миграции;
- откроет панель таблиц `http://127.0.0.1:8090/` только для чтения.

Если PostgreSQL уже установлен, первый запуск скачивает только Node.js (около 35 МБ).
Без PostgreSQL первый запуск скачивает около 365 МБ и может занять несколько минут. Повторный запуск
использует уже скачанные файлы и сохранённую базу. Для остановки дважды щёлкните
`scripts/stop-local-lab5.cmd`. Ручные команды:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\local-lab5.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\local-lab5.ps1 -Action Status
powershell -ExecutionPolicy Bypass -File .\scripts\local-lab5.ps1 -Action Stop
```

Скрипт создаёт для приложения отдельный кластер, поэтому пароль от установленного PostgreSQL
не нужен. По умолчанию база слушает `127.0.0.1:5432`; если порт занят, автоматически
выбирается свободный порт `55432–55442`. Панель доступна только локально, API использует порт `8080`.
Для телефона по USB выполните `adb reverse tcp:8080 tcp:8080`; изменение Windows Firewall
для этого не требуется. Логин базы — `bugs`, база — `bugs`; локальный кластер использует
trust-аутентификацию только на loopback-интерфейсе.

Бэкенд находится в каталоге `backend`. Для запуска на устройстве с Docker из корня репозитория:

```bash
docker compose up --build
```

API будет доступен по адресу `http://localhost:8080/api`. Полное описание методов, структуры
данных и подключения эмулятора или телефона приведено в `backend/README.md`.
Новые игровые методы лабораторных 4–6 описаны в `backend/docs/labs-4-6.md`.
Игровой экран и рекорды подключены к серверу. Сохранение результатов реализовано в PostgreSQL,
Room в этой версии не используется. Во время вылазки играет отдельный зацикленный трек;
теургия накладывает ролик и звук разлома поверх музыки, не останавливая её. Поддержка
физического наклона остаётся будущим этапом.

## Требования

- Windows 10/11 x64;
- Android Studio Quail или новее;
- JDK 21 (встроенный JBR Android Studio подходит; минимум для AGP 9.1 — JDK 17);
- Android SDK 36.1;
- интернет при первой синхронизации Gradle.

Проект использует Android Gradle Plugin 9.1.0 и Gradle 9.3.1.
Проверка пути Android Gradle Plugin отключена, потому что учебная папка Windows содержит кириллицу.

## Запуск в Android Studio

1. Откройте Android Studio.
2. Выберите **Open** и укажите папку `labMob` внутри репозитория.
3. Дождитесь окончания **Gradle Sync** и установки предложенных компонентов SDK.
4. Создайте виртуальное устройство в **Device Manager** либо подключите Android-телефон с включённой USB-отладкой.
5. Запустите бэкенд или укажите адрес уже развёрнутого API через Gradle-параметр `BUGS_API_BASE_URL`.
6. Выберите конфигурацию `app` и нажмите **Run**.

## Проверка из командной строки

Из папки `labMob`:

```powershell
.\gradlew.bat test
.\gradlew.bat assembleDebug
```

Отладочный APK создаётся в `labMob/app/build/outputs/apk/debug/app-debug.apk`.

## Структура этапов

- лабораторная 1 — базовое Android-приложение;
- лабораторная 2 — регистрация игрока и знак зодиака;
- лабораторная 3 — вкладки, правила, авторы и настройки;
- лабораторная 4 — первый игровой район, цели, очки и штрафы;
- лабораторная 5 — PostgreSQL-рекорды и выбор зарегистрированного игрока;
- последующие работы — дополнительные районы, датчики и развитие архитектуры клиента.

История Git сохраняет авторство уже выполненных изменений. Новые коммиты добавляются по мере реальной разработки и проверки проекта.
