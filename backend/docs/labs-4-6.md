# Серверный контракт лабораторных 4–6

Изменения относятся только к серверу. PostgreSQL используется по запросу вместо локальной
Room-базы из задания. Игровая отрисовка, Android SensorManager и воспроизведение аудио
не реализуются на сервере и пока не подключены к этим новым методам в Android-клиенте.

## Лабораторная 4 Игровые раунды

- `GET /api/game/menu` — действия меню и ссылки на API.
- `GET /api/game/rules` — HTML-правила из серверного ресурса.
- `GET /api/game/authors` — список авторов.
- `GET /api/game/catalog` — типы целей, скорости, радиусы, очки, бонус и ключ звукового ресурса.
- `POST /api/rounds` — начать раунд либо восстановить существующий активный.
- `GET /api/rounds/:roundId` — получить актуальное состояние и синхронизировать таймер.
- `POST /api/rounds/:roundId/events` — передать нажатие или бонусное событие.
- `POST /api/rounds/:roundId/finish` — завершить раунд досрочно и сохранить результат.

### Начало раунда

```json
{ "playerId": "123e4567-e89b-42d3-a456-426614174000" }
```

Новый раунд возвращается с HTTP 201, восстановленный — с HTTP 200 и `resumed: true`.
Для одного игрока допустим только один активный раунд. Сложность берётся из текущих настроек игрока,
а настройки фиксируются в момент старта: изменение настроек во время игры влияет
только на следующий раунд.

Ответ содержит объект `round`: `id`, `playerId`, `status`, `serverTime`, `startedAt`,
`endsAt`, `remainingMilliseconds`, `theurgyRemainingMilliseconds`, `score`, `hits`, `misses`, `difficulty`, `settings`,
`targets`, `bonus`, `effect`, `bonusesCollected`.

Все координаты нормализованы: левый верхний угол `(0, 0)`, правый нижний `(1, 1)`.
Клиент преобразует координаты касания из пикселей своего игрового поля в этот диапазон.
Радиус цели применяется в этой же системе, поэтому на прямоугольном поле область попадания
визуально является эллипсом. `velocity` задаёт обычную скорость по каждой оси в долях поля
за секунду; цели отражаются от границ с учётом радиуса. Клиент периодически обновляет
позиции по серверным снимкам. Попадание проверяется на сервере
по положению цели в момент получения запроса, поэтому задержка сети влияет на точность.

Цели живут 12 секунд и заменяются новыми после исчезновения или уничтожения.
Количество целей не превышает `maxInsects`. Беглянка приносит `10 × difficulty`,
Тень `20 × difficulty`; промах снимает 5 очков с ограничением
нижней границы результата нулём.

### Нажатие

```json
{
  "eventId": "123e4567-e89b-42d3-a456-426614174001",
  "type": "tap",
  "x": 0.35,
  "y": 0.6
}
```

Ответ: `event.type = hit` с `targetId` и `awardedPoints` либо `miss` с `penalty`,
а также новый снимок `round`. Событие проверяется по круговой области цели в нормализованном
поле. При наложении целей уничтожается только одна цель за одно нажатие.

`eventId` — новый UUID для каждого действия. При повторной отправке того же события
возвращается сохранённый ответ без повторного начисления. Другие данные с тем же UUID
дают HTTP 409. При сетевом повторе необходимо сохранить исходный UUID и тело запроса.
Сохранённый ответ может быть устаревшим: после повтора клиент запрашивает свежий снимок раунда.

## Лабораторная 5 Игроки результаты и рекорды

- `POST /api/players` — зарегистрировать нового пользователя.
- `GET /api/players` — выбрать ранее зарегистрированного пользователя.
- `GET /api/players/:playerId` — загрузить выбранную анкету.
- `GET /api/players/:playerId/settings` — загрузить серверные настройки.
- `PUT /api/players/:playerId/settings` — сохранить настройки.
- `GET /api/players/:playerId/results?limit=20&offset=0` — история игрока.
- `GET /api/records?limit=20&offset=0&difficulty=3` — лучшие проверенные результаты.

`limit` — от 1 до 100, `offset` — от 0 до 1000000, фильтр сложности — от 1 до 5.
История сортируется от новых раундов к старым. В рекордах остаётся только лучший
подтверждённый результат каждого игрока; при равенстве выше более ранний результат.

Раунд, события и снимок состояния хранятся в PostgreSQL, а не в памяти процесса.
По таймеру серверный обработчик завершает просроченные раунды и сохраняет очки,
попадания, промахи и сложность даже при отключённом клиенте. После перезапуска API
обработчик найдёт просроченные раунды по сохранённому времени окончания.
Обычный запрос состояния также завершает просроченный раунд.

Завершение и запись результата выполняются одной транзакцией. Уникальный `round_id`
защищает от дубликатов при повторном завершении. HTTP 200 от `finish` содержит `round`
и `result`; повторный вызов возвращает тот же результат. Событие после окончания даёт
HTTP 409 с завершённым раундом и результатом.

Прежний `POST /api/results` больше не принимает клиентские очки и возвращает HTTP 410
со ссылкой на `POST /api/rounds/:roundId/finish`. Старые строки результатов сохраняются
в истории с `verified: false`, но не участвуют в рекордах. Только результаты нового
серверного игрового контура имеют `verified: true`.

## Лабораторная 6 Теургия и наклон

По умолчанию бонус появляется каждые 15 секунд; интервал регулируется настройкой
`bonusIntervalSeconds`. Бонус доступен 5 секунд, пропущенные бонусы не накапливаются.
Отдельного сетевого push-канала нет: клиент узнаёт о бонусе при запросах состояния
или из ответа на игровое событие. Для отображения бонусов нужен регулярный опрос API.

### Выбор бонуса

```json
{
  "eventId": "123e4567-e89b-42d3-a456-426614174002",
  "type": "collect_bonus",
  "bonusId": "123e4567-e89b-42d3-a456-426614174003"
}
```

`bonusId` берётся из текущего `round.bonus`. Бонус можно выбрать только один раз.
При успехе `event.type = bonus_collected`, `event.soundCue = target_spotted`.
Четырёхсекундная сцена не тратит время раунда и отражается в `theurgyRemainingMilliseconds`.
После неё `round.effect.type = tilt`. Эффект действует 10 секунд, но не дольше самого раунда.
Текущий Android-клиент не передаёт события наклона, поэтому цели на время действия
бонуса замирают. Разлом и возврат сопровождаются локальными звуками, а игровая музыка
не прерывается.

### Направление наклона

```json
{
  "eventId": "123e4567-e89b-42d3-a456-426614174004",
  "type": "tilt",
  "x": 0.7,
  "y": -0.4
}
```

Клиент нормализует показания датчиков в диапазон `[-1, 1]`. Положительный `x`
означает движение вправо, положительный `y` — вниз. Направление передаётся только
пока активен эффект, рекомендуемая частота — не более 10 событий в секунду.
До первого события направление нулевое. При активном эффекте обычное движение
заменяется направлением наклона со скоростью `effect.speed`, цели прижимаются к краям.
По завершении эффекта обычное движение восстанавливается.

Сервер не обращается к физическим датчикам и не воспроизводит звук: он возвращает
состояние эффекта и звуковую команду. Поля `assetKey` в каталоге — ключи локальных
ресурсов клиента, не URL и не готовые файлы. Мемы и другие изображения в этот
серверный этап не добавлены: для логики API они не требуются.

## Ограничения учебного API

В API пока нет аутентификации и ограничения частоты запросов. UUID игрока и раунда
не являются секретами или токенами авторизации. Этот API предназначен для учебного
локального запуска, не для публичного production-доступа. Для внешнего размещения
нужны авторизация, HTTPS, rate limiting и отдельные секреты PostgreSQL.
